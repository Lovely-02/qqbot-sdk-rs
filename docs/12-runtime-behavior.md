# 12 运行规则卡：和小助手约定好边界 📋

这一章是出发前的规则卡：回复时间、序号缓存、请求额度和连接恢复都以当前实现为准，查边界时直接翻这里。📋

本文说明当前 SDK 的运行规则。接口与字段见 [接口覆盖表](10-api-coverage.md) 和 [字段覆盖](11-field-coverage.md)。

## 被动回复与序号 🌸

| 场景 | 被动回复有效期 | 每条消息回复次数 | 本地序号缓存保留时间   |
| ---- | -------------- | ---------------- | ---------------------- |
| 单聊 | 60 分钟        | 4 次             | 最近一次预约后 60 分钟 |
| 群聊 | 60 分钟        | 通常 5 次，满足群管理权限时 50 次 | 最近一次预约后 60 分钟 |

平台有效期从消息发送时间计算。本地序号缓存不留额外余量，也不延长平台有效期。同一客户端及其克隆按 `msg_id` 共享序号，群内回复和群消息私聊回复也共用原消息的序号计数。显式 `msg_seq` 用于稳定重试，自动序号不因请求失败回退。独立客户端、进程及重启后的计数需由调用方协调。详见 [消息手册](02-messages.md)。

## 请求额度与上传 🌸

`bot_qps` 对所有 QQ API 请求设置共享秒级限额，另叠加接口自身的 QPS/QPM。两级检查通过后才扣额度，本地超限返回 `RateLimited`。Token 获取和 COS 直传不计入该总额度。过期限频键在后续请求中按需清理。跨进程额度、认证类型、单关系频控和自然日配额以平台为准，详见 [工程与排错](07-operations.md)。

分片上传应用平台返回的并发及有限重试配置；未确认所有分片前不合并。预上传与合并只重试尚未发请求的本地限频，避免重复副作用。取消 future 会停止后续调度，已送达平台的请求不能回滚。`md5_10m` 使用前 10002432 字节，详见 [消息手册](02-messages.md)。

图片素材上传先校验文件参数再计算哈希，列表数量与时间戳兼容数字字符串。素材引用、图文卡片与全体提及的用法见 [素材与卡片](09-materials-and-cards.md)。

## 事件与连接 🌸

事件默认遇错停止，可配置继续执行当前事件的其余处理器并返回首个错误。该策略不改变网关恢复与 Webhook 错误返回，业务处理器需保持幂等，详见 [事件与网关](06-events.md)。

网关握手、Hello、鉴权各阶段受请求超时约束。只有非空会话 ID 与已处理序号同时存在时才 Resume，否则重新 Identify。分片管理器协调启动桶、配额与取消；同一网关或管理器运行／清理期间不能重复启动。跨进程配额需外部协调。

## 验证边界 🌸

本地测试不替代真实机器人联调。平台权限、绑定第三方应用后的跨应用标识、自然日配额、文件真实内容与服务端断线补发仍以实际服务为准。原始字段入口用于传递未类型化的数据，不会自动完成所有业务校验。
